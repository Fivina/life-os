# v1.6B Global Workspace, Activity Continuity, and Attention

v1.6B adds host-controlled continuity and decision policy. It does not add prose generation, notification delivery, provider integrations, or automatic canonical mutations.

## State boundaries

- `GlobalWorkspace` is a bounded, temporary situation snapshot reconstructed from authoritative records. It is not persisted as canonical state.
- `ActiveWorkspace` persists real-world activity continuity. It may reference canonical Kitchen, Fitness, Learning, or Planning records, but it never replaces them.
- A conversation and a workspace have separate identities. Either may continue while the other changes.
- `OpenThread` preserves an unresolved possibility; it is not a Goal or Task.
- `ProspectiveThread` preserves a future-conditioned possibility; it is not a scheduled action.
- `AttentionAction` is an executive intent, not a side effect. It cannot deliver a notification, call a tool, or modify a calendar.

## Workspace lifecycle

Workspaces use `ACTIVE`, `PAUSED`, `COMPLETED`, and `ABANDONED`. Multiple open workspaces may survive, but a transactional user lock plus a partial unique database index allows at most one foreground workspace per user. Versioned payload schemas cover Cooking, Workout, Study, and Planning activity. A new service process reconstructs the typed payload from the persisted row without singleton state.

Lifecycle changes emit the existing Events/Outbox records: `workspace.started`, `workspace.updated`, `workspace.paused`, `workspace.resumed`, `workspace.foreground_changed`, `workspace.completed`, and `workspace.abandoned`.

## Reconstructable situation

`GlobalWorkspaceBuilder` reads the foreground and other active workspaces, current PlanBlock, next commitment, recent event references, explicit temporary/self-reported state, pending attention items, open threads, eligible prospective threads, conversation reference, and current WorldRevision. Bounds are fixed at 4 workspace references, 10 recent events, 10 pending attention items, and 8 references from each thread category. Rebuilding after a canonical update reads the newer value.

## Prospective eligibility

Eligibility is contextual and computed rather than stored as permanent truth. v1.6B evaluates `MANUAL`, `DATE_APPROACHING`, `GOAL_STATE_CHANGED`, and `LOCATION_RELEVANT` directly. External trigger types accept explicit observations through the same contract; no polling or connector exists. Past `latest_relevance` prevents resurfacing and can transition the thread to `EXPIRED` without deleting history.

## Attention and curiosity

`AttentionManager` validates the frozen action space and defaults weak or invalid evidence to `SILENT`. Sensitive intents require explicit host authorization. It produces no prose and performs no side effect. `CuriosityPolicy` uses bounded operational values for importance, uncertainty, impact, naturalness, interruption cost, annoyance, and inferability elsewhere; its versioned baseline returns `ASK_NOW`, `DEFER`, or `SKIP`. It has no diagnostic or mental-health inference fields.

Deferred surfaceable intents persist as deduplicated `AttentionItem` rows. No push, email, browser notification, voice, or realtime delivery is connected.

## Bounded cognitive cycle

```text
CognitiveEvent
  -> reconstruct GlobalWorkspace
  -> activate at most 4 relevant contributors
  -> collect at most 4 questions each / 12 total
  -> build bounded DecisionContext
  -> DecisionGateway
  -> AttentionManager and CuriosityPolicy
  -> optional AttentionItem
  -> CognitiveCycleResult
```

The representative contributors cover workspace events, explicit attention candidates, and eligible prospective threads. Decision traces record the situation reference, contributor IDs and versions, question versions, policy versions, and typed provider output. The resulting attention action and pending-item reference are appended through `DecisionAudit`, preserving trace immutability. Provider or validation failure safely returns `SILENT`.

## Flags

- `DECISION_INFRA_ENABLED=false` disables provider execution.
- `COGNITIVE_WORKSPACE_ENABLED=false` disables cognitive-cycle coordination.
- `ATTENTION_POLICY_ENABLED=false` disables attention decisions from the cycle.

All are off by default, so existing Life OS behavior remains unchanged. Workspace and thread services remain explicit programmatic operations.
