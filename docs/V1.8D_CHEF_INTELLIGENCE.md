# v1.8D Chef Intelligence

## Authority Boundary

AI interprets a short meal request into `MealIntent`. It does not select inventory quantities, calculate nutrition, invent prices, create recipes, consume ingredients, or write calendar blocks. Kitchen remains canonical for recipes, inventory, MealPlan, MealHistory, and competency. Fitness and Finance expose bounded typed contracts only.

## Pipeline

```text
meal request
  -> AIGateway structured interpretation
  -> validated MealIntent (meal-intent-v1)
  -> canonical recipe retrieval
  -> hard time/dietary/exclusion/equipment filters
  -> safe inventory and expiry calculation
  -> deterministic nutrition and shopping delta
  -> preference, repetition and technique evidence
  -> named score factors
  -> generic Recommendation / RecommendationOption
  -> MealPlan on explicit selection
  -> ActiveWorkspace CookingSession on explicit start
  -> confirmed actual usage
  -> canonical inventory + MealHistory + competency evidence
```

Malformed or unavailable AI output falls back to a deliberately small deterministic parser that preserves obvious constraints such as a stated minute limit. It never mutates state.

## Typed Bridges

`FitnessNutritionContext` exposes only supported targets, recovery/workout state, goal context, timestamps, completeness and source references. Kitchen combines these with its own consumed-meal history. Missing values remain `None`/unknown.

`GroceryBudgetSignal` exposes only remaining grocery budget, currency, window, status and timestamp. Chef never receives Finance transaction, salary, savings, or merchant history. Missing canonical prices produce an unknown grocery delta, not an estimate invented by AI or code.

## Execution

MealPlan stores planned ingredients, modifications, and a deterministic nutrition snapshot. Serving changes and validated exclusions/substitutions recalculate those snapshots. A CookingSession stores only continuity such as current/previous step, timers, servings, equipment and temporary modifications; it never mirrors inventory.

Completion is idempotent. Actual confirmed ingredient usage may differ from the plan and is consumed through Kitchen's lot-aware service. Expired lots are excluded from availability and consumption. Completion records MealHistory, the generic completed recommendation outcome, and cumulative technique evidence without treating one completion as mastery.
