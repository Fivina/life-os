# v1.6A Decision Infrastructure

v1.6A adds a dormant, typed substrate for small host-controlled decisions. It does not add proactive behavior, change planning, or connect real decision models.

## Two Separate Gateways

`app.ai.gateway.AIGateway` remains the provider-neutral boundary for generative capabilities such as language, reasoning, vision, images, and embeddings.

`app.decision.gateway.DecisionGateway` handles explicit bounded choices. It validates a versioned `DecisionQuestion`, resolves a `DecisionProvider`, validates the returned answer/probabilities, records provider identity and latency, and optionally persists a `CognitiveTrace`. It has no domain, tool, or Planner mutation authority.

## Flow

```text
CognitiveEvent
  -> explicit DecisionContributor
  -> versioned DecisionQuestion
  -> bounded DecisionContextBuilder
  -> DecisionGateway
  -> DecisionProvider
  -> FakeDecisionProvider
  -> validated DecisionResult
  -> immutable CognitiveTrace
  -> append-oriented DecisionAudit outcomes
```

`CognitiveEvent` is a reference-oriented input envelope. It can point to an existing canonical `Event`, world revision, conversation, entities, correlation, and causation without copying full canonical records. It does not replace Events or Outbox and is not automatically subscribed to either.

`DecisionContextBuilder` accepts only explicitly supplied relevant facts, attaches provenance, caps facts/references and serialized size, and remains separate from the assistant's generative context builder. It does not dump conversations, memory, finance, inventory, or global state.

`DecisionQuestion` is immutable and identified by both ID and version. Reusing an ID/version with changed semantics is rejected by the registry. `DecisionResult` distinguishes the selected answer, class probabilities, provider confidence, provider/model versions, host policy version, and latency. None grants permission or canonical write authority.

## Persistence And Privacy

`cognitive_traces` stores explicit event/context references, question identity/version, provider/model/policy metadata, bounded input/output, probabilities, confidence, latency, status, cost placeholder, and explicit action/state references. Completed trace rows are immutable.

`decision_audits` appends downstream outcomes, corrections, overrides, feedback references, and future training eligibility without rewriting historical provider output.

Cognitive traces do not store hidden chain-of-thought, private reasoning, scratchpads, or unrestricted prompts.

## Feature Flags

- `DECISION_INFRA_ENABLED=false`: master switch; disabled mode performs no provider calls or trace writes.
- `DECISION_PROVIDER=fake`: deterministic architecture fixture. Production startup rejects enabling decision infrastructure with this provider.
- `DECISION_TRACING_ENABLED=true`: persists explicit traces when the master switch is enabled.
- `DECISION_POLICY_VERSION=decision-policy-v1`: identifies host validation policy in every successful/failed trace.

No existing v1.1-v1.5 workflow invokes the gateway in v1.6A.

## Benchmark

Run the contract harness from the repository root:

```powershell
backend\.venv\Scripts\python.exe scripts\run_decision_benchmark.py
```

The representative fake cases cover a categorical result, a low-confidence boolean result, and malformed provider output. Results record schema validity, answer, confidence/probabilities, provider/checkpoint identity, latency, and errors. Fake results are contract fixtures, not model-quality measurements.

## Frozen Boundaries

- v1.6B owns Global Workspace, Active Workspaces, Attention, prospective threads, and dynamic contributor activation.
- v1.6C owns `Log feedback`, FeedbackSession, adaptive interviews, and decision training examples.
- v1.6D owns real Laya/Jev providers, shadow execution, disagreement policy, and provider calibration.

Strategic monitoring, intervention policy, response composition, realtime state, and voice remain later work.
