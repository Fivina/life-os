# Life OS v1.9A - Unified Self Core

Self Core is the primary conversation and morning surface. It orchestrates existing services; it is not a database, Planner, GlobalWorkspace, ContextBuilder, Skill, Tool, DecisionGateway, ResponseComposer, or Memory system.

## Request flow

```text
User -> SelfCoreOrchestrator -> ContextBuilder + GlobalWorkspace
     -> deterministic route or SkillRuntime/ToolRegistry/domain service
     -> structured result -> CommunicativeIntent -> ResponseComposer
     -> persistent ConversationMessage
```

Exact foreground-workspace, gym-commitment, active-proposal, Chef, and concert-feasibility requests use bounded deterministic routes. Ambiguous language continues through the existing `self-core` SkillRuntime and AIGateway. Consequential tools keep registry confirmation and idempotency rules. Self Core never creates `PlanBlock` or writes domain rows directly.

PlanProposal explanation reads stored proposal factors. Apply, Modify, and Reject are available through the existing proposal card and through confirmation-required Self Core tools; both paths delegate to `PlanProposalService`, which retains Planner authority and stale-state validation.

## Morning flow

```text
MorningPlanner/current Plan + hard commitments + at-risk trajectories
+ eligible non-silent AttentionItems + active PlanProposal
+ foreground ActiveWorkspace + relevant Kitchen/Finance signals
-> MorningBriefingContext -> CommunicativeIntent -> ResponseComposer
```

The briefing is a reconstructable view. Its fingerprint uses local date, plan identity/version, WorldRevision, policy version, and relevant references. Reopening unchanged state reuses the same identity and cannot duplicate canonical work. Conversation continuity remains server-owned through `ConversationThread` and `ConversationMessage`; realtime continues through the existing WorldRevision state bus.

v1.9A intentionally excludes Quick Capture, a global Review Queue, intelligence settings redesign, voice, and the v2.0 visual redesign.
