# Life OS 2.0 Core Release

## Release Boundary

Version 2.0 integrates and hardens the implemented non-voice product through v1.9B. PostgreSQL/domain services remain canonical, AI remains bounded and optional, and the Planner remains the sole runtime owner of `PlanBlock` creation. No v2.1 voice or personalized-training scope is included.

## Active Architecture

```text
                         Self Core
                             |
          ------------------------------------------
          |                |           |           |
          v                v           v           v
   ContextBuilder   ActiveWorkspace  Skills/Tools  Attention
          |                |                       |
          ----------------+------------------------
                           |
                           v
                    Domain Services
                           |
   --------------------------------------------------------
   |         |        |        |       |      |            |
 Learning  Fitness  Kitchen  Finance  Home   Life      Calendar
                           |
                           v
                  Planner -> Plan/PlanBlock

 Events + Outbox + WorldRevision -> Realtime clients
 DecisionGateway -> Fake/Laya/Jev typed judgment
 AIGateway -> Fake/Gemini language, embeddings, vision
 PostgreSQL -> canonical truth
```

`GlobalWorkspace` is a bounded reconstruction, not storage authority. `ActiveWorkspace` preserves real activity continuity and is not a conversation. `PlanProposal` does not change the current plan until revalidated and accepted. Recommendation selection remains distinct from execution. Notebook thoughts remain distinct from Quick Capture mutations.

## Agent Runtime (2.1C)

Interactive assistant requests use the Agents SDK when `AGENT_RUNTIME=sdk`; `AGENT_RUNTIME=legacy` retains the prior AIGateway/SkillRuntime route for rollback and for deployments not yet configured for the SDK. `AgentModelResolver` applies the existing `AIUsageService` monthly budget and `CapabilityRouter` policy: FAST/REASONING downgrade to ECONOMY at the configured economy threshold, while optional runs are suppressed at the restriction threshold. Direct user requests are not suppressed. Optional host-triggered runs must first pass the versioned `cognition.agent_tier` DecisionGateway question; its result selects only `NO_AGENT` or a bounded capability.

The SDK provider is OpenAI Responses only. `AGENT_PROVIDER=gemini` fails with `agent_provider_not_validated`: although the installed SDK contains an optional LiteLLM adapter, it is not installed or validated for this deployment's Gemini tool-call and usage path. Keep `AGENT_RUNTIME=legacy` to use the existing AIGateway Gemini integration. SDK audit rows aggregate model requests and available token counts per manager/specialist run; trace export remains disabled by default. Tools still use ToolRegistry and domain services, and mutations remain confirmation proposals.

## Golden Scenarios

`scripts/v2_golden_scenarios.json` maps the 13 frozen names to existing service/integration tests: `MORNING_START`, `MISSED_STUDY_RECOVERY`, `COOK_AND_UPDATE_INVENTORY`, `WORKOUT_EXECUTION`, `FINANCE_QUICK_CAPTURE`, `UNCERTAIN_CAPTURE_REVIEW`, `IMPLEMENTATION_IDEA_PARKING`, `MOVIE_PROSPECTIVE_RESURFACE`, `SOCIAL_OPPORTUNITY_FILTER`, `PLAN_PROPOSAL_ACCEPT`, `RESTART_ACTIVE_WORKSPACE`, `TWO_CLIENT_REALTIME`, and `AI_OUTAGE`. The manifest is validated so stale or duplicate mappings fail the release gate.

## Persistence And Restart

PostgreSQL persists domain state, plans/blocks, conversations/messages, ActiveWorkspaces, attention, threads, recommendations/outcomes, feedback/training evidence, Quick Captures, Review Queue items, and provider usage. Fresh-session tests reconstruct typed workspace payloads and server-owned conversations without a Python singleton. `GlobalWorkspace`, morning briefing, and other situation views are rebuilt from newer canonical state.

## Jobs And External Dependencies

| Job | Trigger and safety | External dependency |
| --- | --- | --- |
| Outbox delivery | Worker polling, retry/backoff, persisted attempts | Web Push only when configured |
| Morning planner | Time-gated, user/date idempotent | None |
| Memory consolidation | Threshold/due job, deduplicated evidence | Optional embeddings/AI with fallback |
| Fixture sync | Due standing rules, provider identity reconciliation | API-Football when configured |
| Movie checks | Due prospective threads, bounded/idempotent outcomes | Metadata/showtime adapter when configured |
| Opportunity discovery | Due source state, normalized dedupe | Ticketmaster/other configured sources |

Missing optional credentials produce disabled/degraded provider states, not startup failure. Core planning, canonical CRUD, Quick Capture deterministic intents, Review Queue, workspaces, realtime history, and deterministic responses remain available with all AI disabled.

## Duplication Audit

There is one active implementation for each responsibility: Planner (`app.planning`), canonical Events/Outbox/WorldRevision (`app.events`), conversation store (`app.conversations`), AIGateway (`app.ai.gateway`), DecisionGateway (`app.decision.gateway`), memory retrieval stack (`app.memory`), ActiveWorkspace system (`app.workspaces`), recommendation framework (`app.recommendations`), Quick Capture pipeline (`app.capture`), and Self Core orchestration (`app.self_core`). API route functions are adapters, not competing implementations. Provider interfaces and legacy migration files are compatibility/history, not active truth stores. The retired `app.assistant.gateway` architecture is absent.

## Verification

From `backend`, run:

```powershell
$env:POSTGRES_BIN = 'C:\Program Files\PostgreSQL\17\bin'
.\.venv\Scripts\python.exe ..\scripts\verify_v2_release.py --artifact-dir E:\LifeOSBuild
```

The command compiles backend sources; runs all backend tests; typechecks, tests, and builds the PWA; verifies the full migration chain on disposable PostgreSQL; runs real service/restart/realtime/startup smoke; rehearses `pg_dump`/`pg_restore`; packages source twice and compares hashes. The scripts use strict generated database-name patterns and never downgrade or overwrite the configured database.

## Performance Baseline

The PostgreSQL smoke samples foreground workspace retrieval, reconstructed GlobalWorkspace, Review Queue, idempotent morning briefing, and realtime catch-up. Results are printed as p50/p95 with sample size and should be interpreted with the database location/network path. Provider latency is excluded because optional provider calls are not required for core acceptance.

## Scope Guard

Not included: VoiceGateway, STT, TTS, VAD, microphone streaming, barge-in, wake word, native hands-free companion, personalized Laya training/promotion, generic computer control, or automatic booking/payment.
