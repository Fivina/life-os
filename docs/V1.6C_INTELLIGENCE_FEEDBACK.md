# v1.6C Intelligence Feedback and Quality Evidence

v1.6C adds an explicit, user-controlled evidence path for evaluating completed Life OS decisions. It does not train a model, alter provider routing, mutate canonical domain state, or implement any v1.6D provider.

## Reserved command and isolation

`Log feedback` is a deterministic reserved command. Matching is case-insensitive and whitespace-tolerant; an inline explanation is accepted only after punctuation. Ordinary sentences that merely mention feedback do not activate the workflow. The assistant intercepts the command before conversation persistence, memory curation, skill routing, and AI invocation.

A `FeedbackSession` is a nested interaction, not a new conversation or workspace. It retains references to the parent conversation and foreground `ActiveWorkspace`, but its questions and answers are persisted only in feedback tables. Cancelling or completing it returns to those same parent identities. Workspace canonical state and lifecycle are never changed by feedback.

## Target and frozen context

The target selector considers only the authenticated user's recent, completed, meaningful `CognitiveTrace` records. It prefers an explicit attention item, then the parent conversation and foreground workspace. Benchmark, fixture, housekeeping, worker, background, and non-actionable silent traces are excluded. When a scope is supplied, there is no fallback to an unrelated trace.

At session start, the selected trace, decision question and version, provider/model/policy identity, bounded decision context, attention result, parent references, world revision, and current workspace phase/payload are frozen. Later canonical changes cannot rewrite the evidence being rated. The original trace remains immutable.

## Interview contract

The selector chooses one to four versioned questions from the trace's decision family and the optional inline explanation. Dimensions are stored independently and use a strict `0..5` score or `Skip`, never both. At most one deterministic clarification is allowed. Feedback confidence and scope are explicit fields.

Broad-scope labels are protected. `GENERAL_PREFERENCE` and `PERMANENT_EXPLICIT_RULE` require an explicit matching user statement; otherwise the service safely narrows the label to `EXACT_CASE`. A permanent rule is handed off only as explicit metadata for the existing memory/policy path. It is not silently applied as canonical truth.

## Evidence and quality

Completion appends a `DecisionAudit` and creates one `DecisionTrainingExample` for every non-skipped dimension. Examples preserve separate labels and provenance, including trace, question/version, provider/model/policy, context, workspace phase, attention result, score, scope, confidence, label source, and strength. Skipped answers remain useful interview evidence but are not training examples.

`IntelligenceQualityService` computes aggregates from sessions, responses, and training examples. It reports completion and clarification rates, question counts, score distributions, skip/low/high rates, per-dimension averages, and bounded distributions by scope, workspace, decision family, provider, model, policy, and attention action. Skips are excluded from numeric averages and low-sample dimensions are marked; no aggregate is stored as canonical truth.

## Authority boundaries

- Feedback evidence does not change a `PlanBlock`, workspace, thread, memory, or domain entity.
- `DecisionTrainingExample` is evidence, not a promoted model or automatic rule.
- `DecisionAudit` is append-only outcome evidence; it does not rewrite `CognitiveTrace`.
- The feedback overlay is transport for the typed interview, not a response composer.
- No Laya/Jev provider, shadow inference, checkpoint training, strategic monitor, proposal workflow, realtime bus, voice, or notification delivery is included.

## Persistence and resume

Sessions, responses, audits, and examples are database-backed. A fresh request or process can retrieve an active session and its exact next question without a Python singleton. The resume record preserves the original conversation/workspace IDs and detects if the workspace changed externally during the nested interview.

The feature flag `INTELLIGENCE_FEEDBACK_ENABLED` defaults to `false`. With it disabled, `Log feedback` returns a deterministic disabled result and existing assistant behavior remains unchanged.
