# Life OS v1.7B - Response Composition and Realtime State

## Authority Boundaries

The v1.7B communication path is deliberately split:

```text
structured decision
  -> CommunicativeIntent
  -> versioned SpeakingPolicy
  -> ResponseComposer
  -> final conversation message
```

`CommunicativeIntent` preserves the facts, references, attention action, proposal reference, and wording constraints separately from final prose. `ResponseComposer` is a pure renderer: it receives no SQLAlchemy session, planner service, tool registry, or domain mutation handle. The optional generative path uses `AIGateway` with the `ECONOMY` capability and an empty tool list. Provider failure or invalid generated output falls back to bounded deterministic wording.

Decision character, speaking character, and future voice identity remain separate. Final text is non-authoritative and clients must use canonical domain APIs for state.

## Response Modes and Streaming

Every composed response records one explicit mode:

- `DETERMINISTIC` for exact short statements;
- `GENERATIVE` for bounded synthesis of supplied facts;
- `DETERMINISTIC_FALLBACK` when optional generation fails.

The response stream emits typed `START`, `TEXT_DELTA`, `COMPLETE`, and `ERROR` events. Deterministic responses use one text chunk. A completed response is persisted as a canonical assistant conversation message before `COMPLETE`. A provider failure before output uses deterministic fallback; failure after partial output emits `ERROR`, rolls back, and does not persist a partial sentence as complete.

Message metadata and the linked `DecisionAudit` retain the intent and policy versions, response mode, provider/model/capability, latency, estimated cost when available, trace/proposal references, fallback state, and streaming state. Hidden reasoning is never stored.

## Realtime State Bus

Life OS uses authenticated SSE because v1.7B requires server-to-client invalidation while mutations continue over normal HTTP:

```text
canonical transaction
  -> Event + Outbox + WorldRevision
  -> commit
  -> database-backed SSE catch-up
  -> semantic query invalidation
  -> canonical API refetch
```

The persisted `Event` and `WorldRevision` tables are the recovery authority. Realtime correctness does not depend on an in-memory broker, so reconnects, backend restarts, worker mutations, and multiple backend processes remain recoverable. Rolled-back events are never visible.

`RealtimeStateEvent` includes event ID, ordered world revision, event/domain/entity/operation, semantic invalidation keys, and optional conversation/workspace/correlation references. Events contain references rather than full canonical objects.

## Client Recovery

The frontend owns one app-level `RealtimeStateClient`. It sends authentication in the streaming `fetch` header, persists the last observed revision, suppresses duplicate/stale events, reconnects with bounded exponential backoff, and restarts when authentication changes.

Sequential events invalidate only mapped TanStack Query keys. A revision gap, pruned history, catch-up overflow, or explicit `RESYNC_REQUIRED` event invalidates all queries so the client refetches canonical state. Patches are intentionally not used in v1.7B.

Conversation and ActiveWorkspace remain server-side identities. Conversation messages are revisioned for cross-client delivery; an ActiveWorkspace can be fetched or resumed independently of a browser session or conversation.

## Endpoints

- `POST /api/v1/communication/compose`
- `POST /api/v1/communication/stream`
- `POST /api/v1/communication/plan-proposals/{id}/compose`
- `GET /api/v1/realtime/events?after_revision=N`
- `GET /api/v1/realtime/stream?after_revision=N`
- `GET /api/v1/workspaces`
- `GET /api/v1/workspaces/foreground`
- `GET /api/v1/workspaces/{id}`
- `POST /api/v1/workspaces/{id}/resume`

All endpoints use existing authentication. Tokens are not accepted in realtime query strings.

## Configuration

```text
RESPONSE_COMPOSER_ENABLED=true
RESPONSE_COMPOSER_GENERATIVE_ENABLED=true
REALTIME_STATE_ENABLED=true
REALTIME_POLL_SECONDS=1.0
REALTIME_HISTORY_LIMIT=250
```

Disabling response composition yields no new composed message. Disabling realtime returns `503` from the stream endpoint; ordinary HTTP behavior remains available.

## Schema Decision

v1.7B adds no database tables or migration. Existing conversation message JSON metadata stores response presentation metadata, `DecisionAudit` stores trace linkage, and existing `Event`/`Outbox`/`WorldRevision` records provide committed realtime history. This avoids a parallel event, message, or revision system.

## Scope Boundary

v1.7B does not add voice, STT/TTS, LiveKit, Pipecat, VAD, Idea Notebook, leisure/movie/social discovery, fixture synchronization, or natural-language MealIntent work.
