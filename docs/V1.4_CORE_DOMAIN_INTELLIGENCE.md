# Life OS v1.4 - Core Domain Intelligence

## Architecture Found

Before v1.4, Learning already owned deterministic exam workload, readiness, risk, topic prerequisites, quality-adjusted StudySessions, and candidate variants. Fitness already owned programs, templates, exercise sets, double progression, measurements, recovery, and candidate variants. Goal and Trajectory tables existed but had no product loop. Household recurrence did not exist. Calendar already rendered Planner V2 output and supported execution controls, but only Learning completion reached canonical domain state and candidate synchronization remained manual.

## Domain Planning Contract

`app.domains.base` now defines shared requirement and variant structures plus the domain integration protocol. `app.domains.planning.reconcile_requirements` is the only shared Action-generation path for v1.4 domains. It uses stable requirement identity and preserves historical Actions. `DomainRefreshService` isolates domain failures and runs before planning; `DomainOutboxHandler` supplies event-driven refresh through the existing worker.

Domains own state and need. Planner owns placement. Calendar owns no domain truth.

## Learning Loop

Active exams calculate remaining effective minutes, required daily/rolling pace, readiness, capacity, latest safe start, and normalized risk without AI. The current study occurrence exposes mutually exclusive full, standard, reduced, minimum, and activation variants. Actions link to the exam, topic, Goal, requirement identity, and generation reason.

Calendar completion and partial completion create idempotent StudySessions containing planned and actual duration, slot context, movement/activation evidence, and quality-adjusted progress. Learning then recalculates readiness, risk, workload, and the next requirement. Partial time is never inflated to planned time; Planner debt retains the residual.

## Fitness Loop

An active program uses weekly frequency, sequence, recovery interval, location, recent sessions, and readiness to expose the next workout occurrence. Full, reduced, and minimum variants are mutually exclusive. Recovery is represented both by earliest start and a canonical typed constraint.

Starting a Fitness PlanBlock creates/resumes the canonical WorkoutSession with a planned template snapshot. Sets preserve actual reps, load, and RPE. Completion stores actual duration and whether execution differed from the plan, recalculates deterministic progression, and reconciles the next workout. `fitness.contracts.nutrition_target` is a query boundary for v1.5 Kitchen; no Chef automation was added.

## Goals And Trajectories

Goals now include domain, priority, success condition, progress mode, source linkage, and activation. Trajectories reference domain truth and derive Learning readiness/risk or Fitness measurements without duplicating those records. Minimal Milestones and Weekly Focus are active. Goal priority and weekly focus boost related Action priority but cannot override hard Planner constraints.

## Home Loop

`HouseholdTask` supports daily, interval/every-N-days, weekly, selected weekdays, monthly, and manual interval recurrence. One due occurrence reconciles to shared Action variants; no future occurrence table is expanded. Completion advances `last_completed_at` and `next_due_at`. Skip records an outcome but deliberately leaves the task due.

## Calendar And Events

Calendar shows fixed Commitments and mixed-domain PlanBlocks with domain identity, start, complete, partial, skip, remove-placement, and deterministic explanation controls. Explanations include Action requirement provenance and Goal rationale. Planner overload and unscheduled requirements remain the Needs Attention source.

Canonical mutations and semantic events share the current transaction. Outbox refresh is idempotent. Visible requirement changes and execution outcomes increment WorldRevision; no-op reconciliation does not.

## Memory, Patterns, And Skills

Semantic Memory remains recollection, domain state remains canonical truth, and Personal Learning remains behavioral evidence from PlanBlock outcomes. Learning Coach receives global/learning memory, Fitness Coach global/fitness, and Home Manager global/home. The new Home Manager can read household state and perform confirmed chore operations, but cannot place PlanBlocks or mutate Kitchen. Self Core gains bounded Goals/Home reads and controlled Home writes.

## Migration 0015

- Extends Goal and Trajectory with activation, priority, derivation, risk, and source fields.
- Adds Milestone and WeeklyFocus.
- Extends Action with requirement/source/Goal/Trajectory provenance, generation version, reason, and planning priority.
- Adds Fitness frequency/recovery/location and WorkoutSession planned-versus-actual fields.
- Adds StudySession planned duration, completion status, location, and execution context.
- Adds HouseholdTask with structured recurrence and due/completion state.

All additions use safe defaults and preserve historical domain, Action, Plan, PlanBlock, Goal, and Commitment data.

## AI Independence

Workload arithmetic, recurrence, action generation, constraints, trajectory arithmetic, Planner, Calendar, and execution updates are deterministic. They run with `AI_ENABLED=false`. AI remains limited to interpretation, explanation, coaching, and generative recommendations.

## Deferred

v1.5 still owns rich Chef recommendations, Fridge/receipt ingestion, shopping intelligence, cooking competency, Finance, and nutrition/budget constraints. v2.0 still owns the final Self Core dashboard, universal Quick Capture, Review Queue, proactive briefing/notifications, Settings Intelligence, and full conversational orchestration.
