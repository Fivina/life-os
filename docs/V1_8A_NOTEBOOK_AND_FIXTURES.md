# Life OS v1.8A: Notebook and Standing Calendar Rules

## Authority boundaries

`NotebookEntry` is parked information. Saving an implementation idea creates no Goal,
Action, Requirement, Commitment, Plan, PlanBlock, PlanProposal, project, or roadmap change.
Review and promotion are explicit operations. The initial promotion destination is a typed
manual development review record; it still creates no execution object.

Notebook search combines bounded lexical matching with the existing embedding service.
Embeddings are generated by the existing background memory-job worker. Saving remains
available when embeddings fail, and search falls back to lexical results.

## Fixture flow

```text
StandingCalendarRule
  -> FixtureProvider
  -> NormalizedFixture
  -> FixtureBinding reconciliation
  -> Commitment
  -> Planner
  -> PlanBlock
```

The adapter is provider-neutral. The configured API-Football adapter uses stable provider
fixture IDs, UTC-aware timestamps, deterministic status mapping, and raw payload hashes.
It never calls AI. A successful run schedules the next run exactly 14 days later; failures
retry after six hours and preserve all existing commitments.

`FixtureBinding` preserves provider identity, reconciliation state, explicit suppression,
and protection overrides. Confirmed/scheduled fixtures become hard fixed commitments.
Cancelled, completed, and postponed fixtures are not active Planner obstacles. A postponed
fixture with no confirmed time receives no invented timestamp.

The external source owns fixture time by default. A user may explicitly remove protection
or suppress the binding. Reconciliation respects those choices and does not blindly recreate
deleted or suppressed calendar state.

## Provider configuration

- `FIXTURE_PROVIDER=api_football`
- `API_FOOTBALL_API_KEY=<secret>`
- `API_FOOTBALL_BESIKTAS_TEAM_ID=549`
- `API_FOOTBALL_BASE_URL=https://v3.football.api-sports.io`

Team ID `549` is configurable because API-Football's public documentation requires team-ID
discovery through its dashboard/API. The adapter additionally validates that returned fixtures
actually name Beşiktaş before accepting them.
